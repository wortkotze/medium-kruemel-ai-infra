Aggregiert Google, Bing, DuckDuckGo & ArXiv ohne Tracking. Stellt Agenten eine unlimitierte JSON-Such-API bereit.

  • GET /search?q=...&format=json: Saubere Link- & Snippet-Liste

🌐 Browserless Chromium (:1516)

Ermöglicht Agenten das Headless-Surfen auf dynamischen Websites (React, Vue, SPA) über standardisierte REST-Endpunkte oder WebSocket-CDP.

  • POST /content: Rendert JavaScript & liefert bereinigten DOM
  • POST /screenshot: Visuelle Screenshots für Vision-Modelle
  • POST /pdf: Konvertiert Webdokumente für RAG-Pipelines
  • WebSocket CDP: Direkte Playwright-Anbindung via ws://localhost:1516
⚡ Code Sandbox Runtime (:1517)

Abgesicherte, kurzlebige Ausführungsumgebung für Python- und Shell-Code. Verhindert Ausbrüche und schützt den Host.

  • POST /run: Führt Code aus und liefert stdout, stderr & Exit-Code
  • Non-Root: Läuft unter unprivilegierter UID 1000
  • Ressourcen-Limits: Strikte RAM-Limits (512MB) & Timeouts
  • Isolierte Workspaces: Flüchtiges /tmp mit Bereinigung
Vollständige autonome Agent-Toolchain in Python:
import requests

# Schritt 1: Im Web recherchieren (SearXNG JSON API :1514)
search_res = requests.get("http://localhost:1514/search", params={"q": "LiteLLM Proxy GitHub", "format": "json"}).json()
top_url = search_res["results"][0]["url"]

# Schritt 2: Deep-Content der Webseite extrahieren (Browserless :1516)
page_html = requests.post("http://localhost:1516/content", json={"url": top_url}).text

# Schritt 3: Generierten Berechnungs-/Transformationscode sicher ausführen (Sandbox :1517)
exec_res = requests.post("http://localhost:1517/run", json={
    "code": "print(f'Recherche erfolgreich abgeschlossen auf: {top_url}')",
    "language": "python",
    "timeout": 10
}).json()
print("Sandbox Output:", exec_res.get("stdout"))

🧠 Dual-Memory Architektur: Vektor-Store (Qdrant) vs. Knowledge Graph (Memgraph)

Autonome Agenten und RAG-Pipelines benötigen zwei fundamentale, komplementäre Speicherformen. Bei Krümel AI kombinieren wir semantische Vektorsuche mit strukturiertem Beziehungs-Reasoning zu einem hybriden GraphRAG-System.

Dimension 🗄️ Qdrant (Vektor-Store) 🕸️ Memgraph (Knowledge Graph)
Paradigma Dichte Vektor-Einbettungen (Embeddings) Labeled Property Graph (Knoten, Kanten, Properties)
Kernstärke Unstrukturierte Ähnlichkeitssuche ("Finde relevante Textabschnitte") Multi-Hop Reasoning ("Wie hängen A, B und C zusammen?")
Abfragesprache Kosinus-Ähnlichkeit, Dot-Product, HNSW REST/gRPC Cypher Query Language (OpenCypher via Bolt :7687)
Typische Use-Cases Semantischer Dokument-Upload im Chat, Code-Chunk-Suche, FAQ-Matching Infrastruktur-Topologie, Abhängigkeiten, Agenten-Ontologien, Fakten-Tripel
Hybrid GraphRAG Der Goldstandard: Qdrant findet die relevanten Einstiegsknoten via semantischer Ähnlichkeit. Memgraph folgt den Kanten 1–2 Hops tief, um den vollständigen strukturierten Beziehungskontext ohne Halluzinationen ans LLM zu übergeben.
Cypher Abfragebeispiel in Python (LangGraph & kruemel-ai-agents):
from neo4j import GraphDatabase

# Verbindung zum lokalen Memgraph Bolt-Port (:7687)
driver = GraphDatabase.driver("bolt://localhost:7687", auth=("", ""))

def query_dependencies(tx, service_name):
    query = """
    MATCH (s:Service {name: $name})-[:DEPENDS_ON*1..2]->(dep:Service)
    RETURN s.name AS service, collect(dep.name) AS dependencies
    """
    return [record.data() for record in tx.run(query, name=service_name)]

with driver.session() as session:
    result = session.execute_read(query_dependencies, "litellm")
    print(result)

🤝 Multi-Repo Architektur: kruemel-ai-infra ⟷ kruemel-ai-agents

Um Wartbarkeit, Deployment und Code-Qualität zu maximieren, sind Infrastruktur und Agentenlogik in zwei getrennte Repositories aufgeteilt. Ein automatisierter Systemvertrag verhindert Schnittstellenbrüche.

🏛️ kruemel-ai-infra (Plattform & Runtime)

Hostet alle 15 Container, Datenbanken, LiteLLM RBAC Gateways, Vektorspeicher und FastMCP Server.

  • Verwaltet Ports (:1512–:1517), Docker Compose und Health-Monitoring
  • Generiert Virtual Keys mit strikter Modell- und Tool-Isolation
  • Führt 12 domänenspezifische FastMCP Server in scripts/mcp/ aus
  • Exportiert den zentralen Vertrag via make sync-agents
🤖 kruemel-ai-agents (Logik & Workflows)

Beherbergt die LangGraph Multi-Agenten-Pipelines für die 5 Rollen (PO, Architect, Coder, Researcher, DevOps).

  • Spricht ausschließlich mit LiteLLM (http://localhost:4000/v1)
  • Nutzt rollenspezifische Keys (PO_API_KEY, CODER_API_KEY)
  • Keine hardgecodeten Datenbank- oder Tool-Ports im Python-Code
  • Synchronisiert seine .env vollautomatisch aus der Infra
Synchronisationsbefehl in kruemel-ai-infra:
# Liest Virtual Keys aus LiteLLM, schreibt config/infra_contract.json
# und aktualisiert ../kruemel-ai-agents/.env direkt:
make sync-agents

# Tipp: In Antigravity beide Ordner im Multi-Root Workspace öffnen:
# File -> Add Folder to Workspace... -> kruemel-ai-agents

🌐 Central Agent Registry & Chat Gateway (:1518)

Das Agent Gateway auf http://localhost:1518 dient als dynamische Brücke zwischen kruemel-ai-agents und dem Chat-Frontend (Open WebUI auf :1513):

  • Dynamische Registrierung: Beim Start eines Python-Workers in kruemel-ai-agents ruft dieser POST /api/registry/register auf.
  • Heartbeat & Healthchecks: Alle 20 Sekunden sendet der Worker POST /api/registry/heartbeat. Bleibt der Heartbeat länger als 45s aus, schaltet das Gateway den Agenten automatisch in den Standby-Modus.
  • Open WebUI & Chat-Dispatcher: Open WebUI ruft GET /v1/models vom Gateway ab. Chat-Nachrichten an agent-po, agent-researcher etc. werden via SSE-Stream an den Worker weitergeleitet oder transparent über LiteLLM abgewickelt.
